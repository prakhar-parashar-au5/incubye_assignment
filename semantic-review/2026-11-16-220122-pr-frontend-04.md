# Permission-aware compensation dashboard

Frontend Task 04 adds a protected `/dashboard` that presents scoped headcount, native-currency compensation commitments, breakdowns, recorded changes, upcoming approved changes, and employees without a recent recorded adjustment. The implementation derives its API types and runtime validators from the selected OpenAPI operations, validates URL state before analytics calls, and keeps authenticated data uncached. Independent requests stream behind separate Suspense boundaries, while the browser owns only display and URL-navigation behavior. Source inspection, the installed Next.js 16.4.6 guidance, `npm run check`, `npm run build`, and the recorded browser evidence support the implementation report.

## High-level view

The route starts the summary, breakdown, recent-change, without-adjustment, and permission-filtered option requests together. The summary and options gate the first viewport; the remaining datasets resolve inside their own Suspense boundaries, so a breakdown or list failure does not erase healthy figures (`next-frontend/src/app/dashboard/page.tsx:108-186`).

URL state has an explicit frontend-to-backend mapping, including `status` to `employmentStatus` and `recentDays` to `periodDays`. Known values are checked against generated parameter schemas before dashboard requests begin, repeated values are rejected, and generated links prevent untrusted strings from reaching `router.push` (`next-frontend/src/server/directory-query.ts:75-150`, `next-frontend/src/lib/dashboard-url.ts:89-134`).

The API client remains server-only, sends bearer credentials only from the server, validates all four response bodies against generated schemas, uses `cache: "no-store"`, and does not log tokens or payloads. The dashboard has no `use cache`, `cacheLife`, or `cacheTag`, matching the installed Next.js guidance for fresh request-time data behind Suspense (`next-frontend/src/server/api/client.ts:1-155,274-313`, `next-frontend/src/app/dashboard/page.tsx:49-61`).

Native currencies stay structurally separate in ledger rows and breakdown tables. USD comparison is opt-in and informational, while the exact backend decimal strings remain authoritative; frontend arithmetic is limited to decorative bar widths (`next-frontend/src/components/dashboard/dashboard-sections.tsx:286-407,614-706`).

The tests cover URL validation and mapping, runtime response rejection, safe return paths, exact-value rendering, keyboard behavior, and failure states. This pass verified 192 Vitest tests, lint, generated-contract drift, type checking, and a production build. Playwright was not rerun because its isolated environment requires externally supplied credentials, and `.env` access is prohibited.

## Request-time rendering and partial failure boundaries

The page keeps cookie/session and `searchParams` access below the outer Suspense boundary, which lets Next.js produce the static shell while request-specific content streams. This follows the installed 16.4.6 Cache Components guide: uncached request-time APIs belong behind Suspense, and fresh data should not use `use cache`. The production build identifies `/dashboard` as a Partial Prerender route.

The summary and options determine access, controls, and the first viewport. Breakdown, recent changes, and without-adjustment are consumed by separate async children, each with a section-local error and retry. An empty scope returns before request creation, and backend responses are checked for `hasEmployeeAccess` before rendering (`next-frontend/src/app/dashboard/page.tsx:95-117,248-286`).

## Contract-derived URL and response boundaries

The generator allowlists the four dashboard operations and recursively includes only reachable schemas. The dashboard API methods accept operation-derived query types, and AJV validators compile from the generated OpenAPI subset rather than handwritten interfaces (`next-frontend/scripts/generate-api-contract.mjs:17-41`, `next-frontend/src/server/api/contract.ts:31-74`).

The URL parser validates frontend values with backend parameter schemas, maps breakdowns to API enums, rejects repeated values, and bounds pagination. Invalid known values return before analytics requests. Unknown keys follow the directory route’s existing ignore behavior.

Employee return paths are parsed against a fixed same-origin base and require an exact allowlisted pathname after normalization. This rejects protocol-relative URLs, absolute origins, prefix lookalikes, and traversal while preserving the dashboard query string (`next-frontend/src/lib/directory-url.ts:68-82`, `next-frontend/tests/unit/dashboard.test.ts:149-161`).

## Scoped money presentation and workflow links

The commitment ledger builds one row per native currency and never creates a cross-currency native total. It displays backend-provided base, cash, upcoming commitment, soon-to-join contribution, and signed approved-change impact. Breakdown tables and phone layouts preserve the same currency partition and show exact average, median, minimum, and maximum values. CSS bars are `aria-hidden` and sit next to printed exact values.

Attention counts link to existing employee or salary-request workflows and carry only filters those destinations support. When a request list cannot preserve a dashboard filter, the page names the dropped filters rather than silently implying equivalent results. Dashboard components contain no mutation control.

## Accessibility and interaction coverage

Breakdown tabs implement manual activation: arrow, Home, and End move the roving focus; Enter, Space, or click navigates. Filters and pagination use real links or GET forms as fallbacks, while JavaScript navigation runs through a transition, marks the result region busy, and announces completion. The USD rate context uses an inline button-controlled disclosure rather than hover-only content.

Recorded evidence covers desktop, mobile, Admin, Scoped HR, status breakdown, activity, partial failure, no access, and a 720px viewport approximation of 200% zoom. The report records 93 Playwright passes and 5 project-specific skips and identifies simulated or environment-dependent scenarios (`builder_docs/frontend-builder/responses/04-dashboard-ui.md:176-238`).
