# Salary adjustment and approval workflows

This change adds the complete browser flow for Admin direct salary changes, Scoped HR requests, and Admin request decisions through Next.js server actions backed by the generated OpenAPI contract. It keeps authorization and salary calculation in Express, protects the session token in the server-only boundary, carries idempotency keys on every mutation, and handles stale previews without automatic confirmation. The contract checks, lint, TypeScript checks, 152 unit/component tests, and production build pass, but the approval review omits compensation context required for a safe decision and completion notices trust URL parameters as proof that the current browser performed an action.

**Watch for:** **confirmed** incomplete Admin approval context; **confirmed** forgeable action-success notices.

**Verdict**: NEEDS_CHANGES

## High-level view

The adjustment workspace uses backend preview values as the sole source of salary results. Draft validation catches input-format mistakes, while the backend retains authority over eligibility, scope, salary bands, dates, versions, and confirmation mode. A stale confirmation fetches a new preview and requires another click.

The request list applies backend-defined URL validation and role-aware filters. Request decisions use an inline second confirmation and an idempotency key, but the detail page gives the Admin only the changed target's old and new values before approval. It fetches the employee's full current compensation for version checking but does not render that required decision context.

The post-action pages infer that an action just succeeded from `applied`, `submitted`, and `decided` query parameters. Matching the parameter to current backend state prevents a wholly false state, but any same-site or shared URL can display first-person success copy for an action that browser did not perform.

<details><summary>Details</summary>

## Admin approval lacks the required compensation decision context

**Confirmed:** the human specification requires Admin HR to review the employee's current compensation and requested result before approval (`docs_human/11-salary-adjustments.md:58-63`). The request detail fetches the employee record but uses it only to calculate the latest version and stale warning (`next-frontend/src/app/salary-requests/[requestId]/page.tsx:53-93`). The rendered review shows only the adjusted target's `previousValue` and `proposedValue`, plus method, date, reason, and note (`page.tsx:134-225`). It omits the already-fetched current annual base salary, annual bonus, and annual cash compensation.

Render that backend-provided current compensation beside the requested target result before the decision controls. Keep the stale-version warning when the current version differs, and add component and browser assertions that an Admin sees the full current compensation before confirming approval.

## Query parameters can manufacture action-success notices

**Confirmed:** employee detail accepts any positive `applied` query value and shows “Salary change applied” whenever that version exists in history (`next-frontend/src/app/employees/[employeeCode]/page.tsx:58, 213-225`). Request detail similarly turns `submitted=1`, `decided=approved`, or `decided=cancelled` into first-person completion notices when the persisted request has the matching state (`next-frontend/src/app/salary-requests/[requestId]/page.tsx:91, 103-122`). Opening or sharing those URLs later reproduces a success acknowledgement even when no action occurred in that navigation.

Do not treat caller-controlled URL state as action provenance. Use truthful state-based copy that does not claim the current navigation performed the mutation, or carry a one-time server-controlled completion marker. Add direct-navigation tests for crafted completion parameters.

I did not rerun the Playwright suite because it requires an injected demo credential and isolated seeded MySQL service; no environment file was read. The builder reports 64 passing and 4 skipped Playwright tests, but this review independently verified only the source, fast tests, and production build.
